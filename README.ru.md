# ioBroker Yandex Smart Home Bridge

[![CI](https://github.com/mastergt/ioBroker.yandex-ud-bridge/actions/workflows/ci.yml/badge.svg)](https://github.com/mastergt/ioBroker.yandex-ud-bridge/actions/workflows/ci.yml)

[English](README.md) · [Пример Nginx](examples/nginx/yandex-ud-bridge.conf.example) · [Nginx для HLS-видео](examples/nginx/yandex-ud-bridge-video.conf.example) · [Сообщить об ошибке](https://github.com/mastergt/ioBroker.yandex-ud-bridge/issues)

**ioBroker Yandex Smart Home Bridge** — независимый адаптер, который связывает устройства и состояния **ioBroker** с **Яндекс Умным домом и Алисой** через собственный навык типа «Умный дом». Он позволяет добавить в Алису освещение, розетки, датчики, шторы, ворота, виртуальные кнопки и камеры с HLS-потоком, сохраняя управление устройствами в ioBroker.

**Автор:** Sergey Batayshchikov · **Первые публичные версии на GitHub:** с v0.3.16 · **Первая публикация в npm:** v0.3.26 (планируется) · **Лицензия:** MIT.

> Неофициальный проект сообщества. Не разработан и не поддерживается Яндексом или командой ioBroker. Пока адаптер не включён в официальный каталог ioBroker, установка выполняется из GitHub.

## Принцип работы

```text
Алиса / приложение «Дом с Алисой»
           |
           | Интернет, HTTPS, OAuth 2.0
           v
Домен и публичный IP -> Nginx (443, TLS)
                              |
                              | HTTP на 127.0.0.1:8096
                              v
                    Yandex UD Bridge (ioBroker)
                              |
                              | Чтение / запись ioBroker States
                              v
               Zigbee / Tuya / MQTT / JavaScript / ...
```

В адаптер встроены **API провайдера Яндекс Умного дома** и **собственный OAuth 2.0-сервер**, поэтому отдельный сервис авторизации не нужен. Яндекс обращается к публичному HTTPS-адресу, получает перечень настроенных устройств и их возможностей, запрашивает значения и передаёт команды. Адаптер преобразует команды в значения ioBroker States, а значения состояний — в формат Яндекса.

Сами Zigbee, Tuya, MQTT и прочие устройства продолжают обслуживаться их обычными адаптерами ioBroker. Yandex UD Bridge не заменяет эти адаптеры и не общается с радиооборудованием напрямую. Запись команды в ioBroker **не гарантирует**, что физическое устройство выполнило движение.

## Возможности

- Добавление устройств и их функций через веб-интерфейс ioBroker Admin, с выбором объектов в штатном дереве.
- Настройка чтения и записи, в том числе отдельного объекта обратной связи.
- **Двусторонние преобразования без JSON:** таблицы соответствий, числовые значения, пороги, преобразования положения.
- Пример применения — ворота: Яндекс `true/false` ↔ Zigbee `position` `100/0` (если у вашего устройства именно такая шкала).
- Доступность: привязка к состоянию `available`, инверсия или режим **«Всегда доступен»**.
- Расширенная диагностика цепочки «Яндекс → маппинг → ioBroker State → результат записи».
- Экспорт и восстановление настроек адаптера, включая сохранённые OAuth-токены.
- Поддержка камер через ссылку на **HLS** (при наличии отдельного сервера видеопотока).

## Требования

1. **ioBroker:** js-controller **5+**, Admin **6+**, **Node.js 20+**. Требования указаны также в `io-package.json` и `package.json`.
2. **Рабочие объекты State** ваших устройств в ioBroker (через Zigbee, Tuya, MQTT, JavaScript и другие адаптеры).
3. **Аккаунт Яндекса** для [консоли разработчика Яндекс Диалогов](https://dialogs.yandex.ru/developer/) и создания навыка **«Умный дом»**.
4. **«Белый» публичный IP-адрес**, доступный с серверов Яндекса, либо другое реально доступное из Интернета решение (например, VPS и обратный туннель). Для простой схемы рекомендуется публичный **IPv4**, доменное имя и перенаправление внешнего TCP-порта **443** на Nginx. Статический IP удобнее, но с динамическим IP возможен DDNS. Если провайдер использует **CGNAT**, обычный проброс портов на роутере не заработает.
5. **Домен** с корректной DNS-записью и **HTTPS** с доверенным TLS-сертификатом и полной цепочкой сертификатов (например, Let's Encrypt). Сам ioBroker может находиться в локальной сети.
6. **Nginx** или другой reverse proxy для передачи запросов к адаптеру. Не открывайте порт ioBroker Admin в Интернет.
7. Необязательно: **go2rtc** или другой сервис HLS, если хотите выводить камеры в Яндекс.

Наличие «белого» IP требуется **для прямого подключения**, а не принципиально для любых схем: его может заменить публичный VPS/прокси. Ключевое требование — устойчивый внешний HTTPS-доступ с серверов Яндекса и из браузера при привязке аккаунта.

## Установка адаптера из GitHub

Пока адаптер не опубликован в официальном каталоге, откройте **ioBroker Admin → Адаптеры → Установка из собственного источника → GitHub** и укажите:

```text
https://github.com/mastergt/ioBroker.yandex-ud-bridge
```

Установите адаптер, создайте экземпляр `yandex-ud-bridge.0` и откройте его настройки. При возможности используйте конкретный GitHub-релиз/тег, а не постоянно изменяющуюся ветку. **Предварительно сохраните резервную копию ioBroker.**

Для разработчиков: `npm install`, `npm run check`, `npm test`. Не путайте публикацию исходников на GitHub с публикацией в npm или официальном репозитории адаптеров — это отдельные этапы.

> **Интерфейс Admin (v0.3.18+):** настройки экземпляра — JSON Config со стандартными `bind`/`port`, а редактор устройств в боковой вкладке работает без Materialize/FancyTree. Старые `listenHost`/`listenPort` автоматически переносятся при первом запуске, при этом устройства, маппинги и OAuth-токены сохраняются. Подробнее — [миграция Admin](docs/ADMIN_MIGRATION.md).

## Первичная настройка ioBroker

1. В настройках экземпляра укажите адрес прослушивания **`127.0.0.1`** и порт **`8096`**, если Nginx работает на этом же сервере. Внешним пользователям порт `8096` открывать **не надо**. Если Nginx находится на другом хосте, используйте приватный защищённый сегмент сети.
2. Укажите **публичный HTTPS URL**, например `https://smart.example.com` — без дополнительных путей вроде `/provider/`.
3. В разделе **OAuth** сгенерируйте **Client ID**, **Client Secret**, логин и пароль для привязки аккаунта. Сохраните настройки экземпляра. Это отдельные реквизиты: Client ID/Secret используются навыком, а логин/пароль вводятся вами при привязке через браузер.
4. Настройте домен, сертификат и Nginx по примеру ниже. Проверьте доступ извне (например, с мобильного Интернета):
   ```bash
   curl -I https://smart.example.com/provider/v1.0/
   ```
   Нормальный результат для этого адреса — HTTP **200**. Этот запрос проверяет доступность сервера, но не авторизацию и выполнение команд.
5. В боковой вкладке **«Яндекс Умный дом»** добавьте устройства: выберите тип, комнату, возможность или свойство, затем объект ioBroker для чтения/записи.
6. При необходимости настройте **преобразования в обе стороны** и сохраните. Затем протестируйте устройства из Яндекса.

### Пример: числовое управление воротами

У некоторых устройств Zigbee открытие — это `position=100`, а закрытие — `position=0`:

| Яндекс → ioBroker | Запись в `position` | ioBroker → Яндекс |
|---|---:|---|
| `true` (открыть) | `100` (число) | `100` → `true` |
| `false` (закрыть) | `0` (число) | `0` → `false` |

Выберите соответствующий State, например `zigbee.0.device.position`, и в таблицах маппинга укажите значения без ручного JSON. Числа `0` и `100` автоматически сохраняются **как числа**, а не строки `"0"` и `"100"`. Для промежуточных положений можно задать порог — например, значение **больше 0** трактовать как «открыто». Сначала убедитесь, что конкретное устройство использует такую шкалу.

### Доступность и диагностика

**«Доступность»** находится среди возможностей и свойств устройства. Можно выбрать ioBroker State `available`, инвертировать его или включить **«Всегда доступен»** (подходит виртуальным кнопкам и некоторым устройствам с неверным offline-статусом). Режим влияет только на отображение онлайн/офлайн в Яндексе и **не гарантирует** выполнения команд физическим устройством.

При включении подробного логирования видна цепочка: полученная команда Яндекса → выбранная функция → преобразование значения → ID объекта ioBroker → результат записи. Не выкладывайте полные логи с чувствительной информацией в открытый доступ.

## Создание навыка «Умный дом» в Яндекс Диалогах

1. Перейдите на [dialogs.yandex.ru/developer](https://dialogs.yandex.ru/developer/). Нажмите **«Создать диалог» → «Умный дом»**. Задайте название, описание и иконку. Для собственного дома рекомендуем **«Приватный»** тип доступа; публичный навык — отдельная процедура публикации и модерации Яндекса.
2. В настройках навыка укажите **Endpoint URL**:
   ```text
   https://smart.example.com/provider/
   ```
   **Важно:** это базовый URL провайдера. Не указывайте вместо него `/provider/v1.0/` — Яндекс сам запрашивает `/provider/v1.0/user/devices`, `/provider/v1.0/user/devices/action` и другие методы.
3. Откройте раздел **«Связка аккаунтов»** и заполните:

   | Поле Яндекса | Значение из настроек адаптера |
   |---|---|
   | Идентификатор приложения (Client ID) | Сгенерированный **OAuth Client ID** |
   | Секрет приложения (Client Secret) | Сгенерированный **OAuth Client Secret** |
   | URL авторизации | `https://smart.example.com/oauth/authorize` |
   | URL получения токена | `https://smart.example.com/oauth/token` |
   | URL обновления токена | `https://smart.example.com/oauth/token` |

   Адрес возврата после авторизации (`redirect_uri`) обрабатывает сам адаптер; разрешённый Яндексом URL: `https://social.yandex.net/broker/redirect`. Реквизиты адаптера **не являются** паролем от Яндекса и не требуют отдельного приложения в Яндекс ID.
4. Сохраните настройки навыка, выполните тестирование и публикацию приватного навыка в консоли. После этого откройте приложение **«Дом с Алисой»**, добавьте/привяжите соответствующий навык и войдите с помощью **локального логина и пароля**, созданных в адаптере.
5. Обновите устройства в Яндексе и проверьте получение перечня, чтение состояния, управление, доступность и работу после перезапуска ioBroker. Для поиска проблем используйте диагностику OAuth/API и подробные логи адаптера.

Актуальные инструкции Яндекса: [создание навыка](https://yandex.ru/dev/dialogs/smart-home/doc/ru/start), [связка аккаунтов](https://yandex.ru/dev/dialogs/smart-home/doc/ru/auth/add-skill-to-console), [принцип OAuth](https://yandex.ru/dev/dialogs/smart-home/doc/ru/auth/how-it-works).

## Настройка Nginx для адаптера

Готовый файл: **[`examples/nginx/yandex-ud-bridge.conf.example`](examples/nginx/yandex-ud-bridge.conf.example)**. Поменяйте домен и пути к сертификату на свои. Важно пробрасывать **весь выделенный домен** на адаптер, сохраняя исходные URI: и `/provider/...`, и `/oauth/...`.

```nginx
server {
    listen 443 ssl;
    server_name smart.example.com;
    ssl_certificate /etc/letsencrypt/live/smart.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/smart.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8096;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 5s;
        proxy_read_timeout 30s;
    }
}
```

Полный `.example` также содержит редирект HTTP → HTTPS. Установите сертификат Let's Encrypt (или другой доверенный), проверьте `nginx -t`, затем перезагрузите Nginx. **Публично открыт только 443**, сам адаптер слушает `127.0.0.1:8096`.

## Проброс видеопотока камер (отдельный Nginx example)

Для функции **`devices.capabilities.video_stream`** адаптер должен возвращать публичный адрес **HLS-плейлиста**. Он **не перекодирует RTSP и не проксирует видео**. Если камера отдаёт RTSP, для HLS нужен отдельный сервис (например, [go2rtc](https://go2rtc.org/)). Можно выделить отдельный домен `video.example.com` и направлять его на локальный go2rtc.

- **Пример Nginx:** [`examples/nginx/yandex-ud-bridge-video.conf.example`](examples/nginx/yandex-ud-bridge-video.conf.example) — проксирование только HLS-маршрутов go2rtc, без публикации его административного интерфейса.
- **Пример ссылки для поля HLS:** `https://video.example.com/api/stream.m3u8?src=camera1` (имя потока `camera1` задано в go2rtc).
- **Требования Яндекса:** HLS; видеокодек **H.264**, разрешение не более **1920×1080**; звук при наличии — **AAC**. В ответе с плейлистом должны быть `Content-Type: application/vnd.apple.mpegurl` и `Access-Control-Allow-Origin: https://yastatic.net`. Все сегменты также должны быть доступны извне по HTTPS. [Официальная спецификация video_stream](https://yandex.ru/dev/dialogs/smart-home/doc/ru/concepts/video_stream).
- **Важно о безопасности:** пример ниже показывает сетевую связность, но **не обеспечивает авторизацию для просмотра камеры**. Любой, кому известен общедоступный URL, потенциально сможет смотреть видео. Для реального использования необходимы ограничение доступа или временные подписанные ссылки, совместимые с плеером Яндекса. Не выставляйте в Интернет панель go2rtc и произвольные внутренние RTSP-адреса.

## Резервное копирование и восстановление

В настройках экземпляра выберите **«Резервная копия» → «Скачать полный бэкап»**. Файл включает настройки адаптера, устройства, двусторонние преобразования и локальное хранилище OAuth-токенов. При восстановлении используйте **«Восстановить из файла»** и перезапустите экземпляр.

**Файл содержит чувствительные данные в открытом виде**, включая секреты и токены. Храните его как базу паролей, не прикладывайте к GitHub Issues и не добавляйте в репозиторий.

Бэкап **не восстанавливает** другие адаптеры ioBroker, объекты устройств вне самого моста, JS-скрипты, VIS, настройки Яндекс Диалогов, Nginx, сертификаты и HLS-сервер. На другом сервере эти компоненты необходимо восстановить отдельно, чтобы функциональность сохранилась полностью.

## Диагностика проблем

| Проблема | Что проверить |
|---|---|
| Яндекс не подключается | Публичный адрес/CGNAT, DNS, HTTPS/TLS, порт 443, Nginx и `/provider/v1.0/` |
| Ошибка привязки аккаунта | Client ID/Secret, URLs авторизации и токена, локальный логин/пароль, redirect |
| Не появилось устройство | Видимость устройства, его функции и привязки, обновление списка в Яндексе |
| Команда не исполняется | Целевой State, `ack=false`, преобразование и тип значения (`0` — число, `"0"` — строка), логи Zigbee/Tuya |
| Камера не показывается | HLS-плейлист, HTTPS-сегменты, H.264/AAC, CORS, внешняя доступность |
| Устройство ошибочно офлайн | Привязка доступности, инверсия или «Всегда доступен» |

Сообщения об ошибках: [GitHub Issues](https://github.com/mastergt/ioBroker.yandex-ud-bridge/issues). Перед отправкой удаляйте из логов секреты, токены, адреса внутренних устройств и личные данные. Уязвимости отправляйте приватно согласно [SECURITY.md](SECURITY.md).

## Безопасность Nginx и OAuth

При расположении Nginx на том же сервере оставьте HTTP-адаптер на `127.0.0.1`.
Опцию **«Доверять X-Real-IP от локального Nginx»** включайте, только если Nginx
перезаписывает `X-Real-IP` значением `$remote_addr`. По умолчанию настройка
выключена. Дополнительное ограничение запросов к OAuth приведено в
[примере Nginx](examples/nginx/yandex-ud-bridge.conf.example).
