# Версия 0.3.6 — профиль Tuya Curtain и преобразования значений

**Обновление поверх v0.3.5:** ID устройств, привязки, OAuth-токены, логины, настройки камер и функции остальных устройств не изменяются автоматически. `readTransform` и `writeTransform` необязательны: при их отсутствии сохраняется прежнее поведение `mapping`.

## Готовый профиль «Шторы Tuya» (исправлен: одно поле `percent_control`)

Подтверждённая семантика **конкретных штор пользователя**: `tuya.0.DEVICE.2` (`percent_control`) — **0% полностью открыты, 100% полностью закрыты**. Действия строками `open` / `close` через `.1` для этих штор не работают. Другие модели Tuya могут использовать иную шкалу — не применяй профиль без проверки.

1. Открой **ioBroker Admin → Яндекс Умный дом → Устройства → нужные шторы**.
2. В разделе **Готовый профиль · Шторы Tuya** выбери **Tuya percent_control (.2)**.
3. Нажми **Применить профиль к этим шторам**. Действие только сохраняет настройки редактора и **не отправляет команд мотору**.
4. Нужен **только State `.2`** для управления и чтения положения; `.1` и `.3` не используются. `.online` остаётся необязательным отдельным признаком доступности, если подтверждён в ioBroker.
5. Нажми **Сохранить**. Проверь команды в тестовом навыке, не отключая `yandex2mqtt`.

| Функция Яндекса | State для чтения и записи | Значения и преобразование |
|---|---|---|
| `on_off.on` | `tuya.0.DEVICE.2` | `true` (открыть) → `0`; `false` (закрыть) → `100`. Чтение: `<100` → `true`, `100` → `false` |
| `range.open` | `tuya.0.DEVICE.2` | Чтение и запись: `100 − x`. Яндекс `0` → Tuya `100` (закрыты); Яндекс `100` → Tuya `0` (открыты) |
| Доступность | `tuya.0.DEVICE.online`, если существует | `true`/`false` |

Важное ограничение: `percent_control` может показывать **заданное положение**, а не фактическое положение двигателя. Поэтому статус Алисы будет основан на доступном `.2` и может опережать реальное движение штор. Если нужен фактический процент, потребуется отдельный достоверный State — но профиль намеренно работает только с `.2`.

Профиль затрагивает **только две функции текущих штор**; не меняет ID устройств, OAuth, камеры, прочие привязки или MQTT. Повторное применение не создаёт дубликатов.

### Универсальные преобразования

В настройках каждой функции появились независимые блоки **«Чтение: ioBroker → Яндекс»** и **«Запись: Яндекс → ioBroker»**.

- `boolean`: преобразование известного булевого состояния в `true/false`;
- `lookup`: таблица `[вход, выход]` с точным сопоставлением типов;
- `threshold`: сравнение числового значения с порогом (`gt`, `gte`, `lt`, `lte`, `eq`, `neq`);
- `invert`: формула `max − x`;
- `scale`: линейное преобразование между диапазонами `from` и `to`.

Пример полей профиля:

```json
{
  "readTransform": "{\"type\":\"threshold\",\"operator\":\"lt\",\"value\":100}",
  "writeTransform": "{\"type\":\"lookup\",\"pairs\":[[true,0],[false,100]]}"
}
```

В адаптере преобразования выполняются без `eval`/пользовательского JavaScript. При неверной таблице команда отвергается **без записи в объект ioBroker**. При отсутствии настроенного нового преобразования старое поле `mapping` работает как раньше; если новое задано, оно имеет приоритет над `mapping` в соответствующем направлении.

**Установка на действующий ioBroker:** сначала сделать копию `system.adapter.yandex-ud-bridge.0`, затем из `/opt/iobroker` выполнить `npm install /path/to/iobroker.yandex-ud-bridge-0.3.6.tgz --omit=dev`, `iobroker upload yandex-ud-bridge`, `iobroker restart yandex-ud-bridge.0`. Никакие привязки или OAuth-учётные данные для обновления не надо пересоздавать.

# ioBroker.yandex-ud-bridge — устройство и API

Полностью автономный адаптер для публикации устройств ioBroker в **собственном навыке** Яндекс Умного дома. Старый `yandex2mqtt` после миграции не нужен.

## Исправление 0.2.3

Исправлен вызов стандартного `sendTo(null, command, payload, callback)` в ioBroker Materialize Admin вместо отсутствующего `socket.sendTo`. Если дерево не удалось прочитать, редактор теперь показывает конкретную ошибку, а не пустое окно; доступна кнопка повторной загрузки. На сервере ошибки перечисления состояний больше не маскируются пустым списком.

## Что реализовано

- Новый интерфейс в боковом меню **ioBroker Admin → Яндекс Умный дом**: отдельные карточки устройств, шаблоны (лампа, розетка, датчики, шторы, пылесос, камера, термостат), управление функциями без огромной таблицы, простой/экспертный режим.
- Выбор состояния ioBroker в **модальном дереве объектов** (device → channel → state) с поиском по ID, названию, common.role и показом доступности записи. Для обычного управления нужен один State ID; отдельный State ID команды включается только при необходимости.
- На уровне устройства можно выбрать **online State ID** (`true` = в сети, `false` = не в сети) и при необходимости инвертировать его. Яндекс получит DEVICE_UNREACHABLE при недоступности; через настроенные callback-уведомления передаётся status = online/offline.
- REST API Яндекс-провайдера: `HEAD /provider/v1.0/`, `GET /provider/v1.0/user/devices`, `POST /provider/v1.0/user/devices/query`, `POST /provider/v1.0/user/devices/action`, `POST /provider/v1.0/user/unlink`.
- Свой OAuth2 Authorization Code Grant: страницы входа, обмен кода на access и refresh токены, обновление токенов, отзыв привязки; без внешнего OAuth сервера.
- OAuth-токены **в виде SHA-256 хэшей**, сохраняются в `iobroker-data/yandex-ud-bridge.0/oauth-tokens.json` (права 0600) и переживают перезапуск. Client secret и пароль входа защищены механизмом encryptedNative ioBroker.
- Однократный импорт **только устройств** из старого `config.js` через диалог выбора файла в браузере; без выполнения JavaScript, паролей MQTT, HTTPS-ключей и старой базы `loki.json`.
- При импорте MQTT-привязки заменяются на **отключённые** функции с подсказками о старых топиках. Для работы каждой функции требуется сопоставить состояния ioBroker.
- Сохранение существующих ID устройств для сохранения сценариев, где возможно.
- Опциональные событийные callback-уведомления Яндексу.

1. **Сервер и HTTPS:** `127.0.0.1`, порт `8096`. Не публикуйте HTTP в интернет напрямую.
2. **Авторизация:** `Client ID`, `Client secret`, локальный логин, локальный пароль, ID пользователя (например, `1`).
3. **Устройства:** откройте боковой пункт **«Яндекс Умный дом»** и добавьте из шаблона. Для переноса старой конфигурации откройте **Экземпляры → yandex-ud-bridge.0 → Настройки → Импорт config.js**, сохраните настройки, затем вернитесь в боковую вкладку.
4. В карточке выберите **Состояние устройства → Выбрать…** и укажите State ID из дерева. Оно применяется и для чтения, и для записи. Если устройство имеет отдельный объект для команд, поставьте флажок **«Управление через отдельный объект ioBroker»**. Для датчиков команда не нужна.
5. По желанию в карточке настройте **Доступность устройства · online** через то же дерево. `true/1/online` означает доступно, `false/0/offline` — недоступно. При другом соглашении используйте инверсию; неизвестное или отсутствующее значение трактуется как offline.
6. Для отображения «Не в сети» в приложении «Дом с Алисой» включите callback-уведомления на вкладке **Дополнительно** (ID навыка, OAuth токен владельца навыка и флажок). Навык должен поддерживать callbacks. Статус online/offline не связан с функцией Вкл/выкл.
7. При настройке устройств нажмите **«Сохранить изменения»** в нашей боковой вкладке. Для OAuth/HTTP или импорта нажмите штатную кнопку **«Сохранить»** в настройках экземпляра. После изменения Native-конфигурации ioBroker может перезапустить адаптер.
8. В разделе **«Яндекс Умный дом → Проверка»** можно посмотреть JSON устройств. Неподключённые функции не публикуются.

**Важная особенность импорта:** импортируются все 30 исходных устройств / 46 функций из приложенного примера, но функции из MQTT останутся **выключенными**, пока вы не привяжете соответствующие ioBroker State IDs. Некоторые устройства могут пока не отображаться в Яндексе. Миграция не подключает MQTT автоматически.

## Настройка собственного навыка Яндекса

Пусть внешний домен для навыка `https://yandex.example.org`. Не используйте действующий адрес своего сервера как пример без проверки.

Нужно настроить **один HTTPS reverse proxy** до `http://127.0.0.1:8096` и четыре URL в кабинете разработчика навыка:

| Назначение | URL |
|---|---|
| Endpoint URL | `https://yandex.example.org/provider/` |
| Authorization URL | `https://yandex.example.org/oauth/authorize` |
| Token URL | `https://yandex.example.org/oauth/token` |
| Refresh URL | `https://yandex.example.org/oauth/token` |

**Новый OAuth НЕ использует старый `loki.json` и не распознаёт старые Bearer-токены.** Сначала настройте и проверьте новый сервер на отдельном HTTPS-домене или пути, затем измените адреса в навыке Яндекса, после этого **отвяжите и заново привяжите аккаунт** в «Дом с Алисой». Только после удачной проверки выключайте `yandex2mqtt`.

Пример nginx (использовать внутри существующего `server { listen 443 ssl; ... }`, не дублировать SSL-конфигурацию):

```nginx
location = /oauth/authorize { proxy_pass http://127.0.0.1:8096; proxy_set_header Host $host; }
location = /oauth/token { proxy_pass http://127.0.0.1:8096; proxy_set_header Host $host; }
location /provider/ { proxy_pass http://127.0.0.1:8096; proxy_set_header Host $host; }
```

Не проксируйте `/` к адаптеру и не выставляйте административные порты ioBroker наружу. Защитите сервер TLS, файерволом и ограничениями на уровне reverse proxy.

## Локальные тесты API

```bash
curl -i -I http://127.0.0.1:8096/provider/v1.0/
curl -i http://127.0.0.1:8096/provider/v1.0/user/devices
```

Первый должен дать `200 OK`, второй без токена — `401 Unauthorized`.

Полный тест OAuth требует `client_id`, `client_secret`, логин/пароль и фактического HTTPS-редиректа Яндекса. Не отправляйте секреты в чат или логи.

## Известные ограничения

- Это пилотная версия; реальная работа модального дерева с вашим Admin 7 / js-controller 7 ещё требует проверки на сервере (автоматические тесты backend пройдены, headless-браузер в среде сборки не завершил запуск).
- Поддерживается один локальный OAuth-пользователь на экземпляр. Все включённые устройства доступны этому пользователю. Устаревший параметр `allowedUsers` игнорируется и удаляется при сохранении настроек.
- OAuth-коды авторизации хранятся в оперативной памяти 5 минут; токены сохраняются на диск и переживают перезапуск.
- Для импорта нужен синтаксис **литерального JS-объекта** `module.exports = {...}`. Вычисления, require(), переменные, JS-функции не принимаются и не выполняются.
- Автоподбор типа функции по ioBroker role пока ограничен шаблонами и подписанными вариантами state ID; полностью автоматическое определение всех устройств зависит от качества common.role.
- Умение `color_setting` (HSV), продвинутые режимы и камеры требуют проверки соответствий состояний и параметров на реальном оборудовании.
- При выключении callback Яндекс будет получать данные при запросах, но не push-события.
- Отсутствует end-to-end проверка HTTPS и навыка Яндекса: она должна выполняться на работающем сервере.

## Особенности доступности

- `onlineStateId` — необязательное поле у устройства, не capability и не property.
- В запросах Яндекса к `/query` при `offline` возвращается `{ "id": "...", "error_code": "DEVICE_UNREACHABLE" }`. В `/action` — `action_result.status=ERROR, error_code=DEVICE_UNREACHABLE`; команда не исполняется.
- Когда настроены callbacks, переход `online/offline` формирует отдельное сообщение `status` для Яндекса. `status_info.reportable` объявляется `true` только при указанном онлайн-объекте и заполненных callback-параметрах.
- Если онлайн-объект не настроен, устройство считается доступным (старое поведение версии 0.2.0). Когда онлайн-объект настроен, но отсутствует или содержит неизвестное значение, устройство считается недоступным, чтобы избежать неуспешных команд.
- Не путайте bool `on_off` (питание) и `online` (связь): лампа может быть выключена, но находиться в сети.

Документация Яндекса: [обнаружение устройств](https://yandex.ru/dev/dialogs/smart-home/doc/ru/reference/get-devices) и [callback состояний](https://yandex.ru/dev/dialogs/smart-home/doc/ru/reference-alerts/post-skill_id-callback-state).

## Изменения в 0.2.9

- Удалено поле «Доступно пользователям (ID через запятую)» из карточки устройства.
- Единственный настроенный OAuth-пользователь видит все устройства с включённым флажком «Показывать в Яндексе».
- Ранее записанные `allowedUsers` больше не влияют на выдачу; при сохранении устройств через боковую вкладку или настройки экземпляра это поле удаляется.
- OAuth `oauthUserId` остаётся неизменным: он обязателен в ответе Яндексу, а изменения учётной записи требуют повторной привязки навыка.
- При импорте legacy `config.js` списки пользователей не переносятся.


### OAuth — мастер настройки (0.3.0)

В **Экземпляры → Yandex UD Bridge → Авторизация** нажмите **«Создать OAuth автоматически»**,
если все четыре поля Client ID, Client Secret, логина и пароля пустые.
Ключи создаются в браузере из WebCrypto; слабый псевдослучайный генератор не применяется.
Нажмите штатную кнопку **«Сохранить»** и дождитесь перезапуска экземпляра.
Не нажимайте «Создать» для действующего навыка: существующие и частично заполненные
реквизиты не заменяются автоматически.

В **Сервер и HTTPS** введите публичный HTTPS-домен (например, `https://smart.example.ru`).
Он используется лишь для подготовки адресов в интерфейсе, **не устанавливает сертификат**
и **не меняет nginx**. После сохранения OAuth-вкладка покажет готовые адреса и кнопку
копирования полей для Яндекс Диалогов. Там они всё ещё задаются в консоли навыка.
Для успешной OAuth-привязки HTTPS прокси должен направлять на локальный порт адаптера
пути `/oauth/authorize`, `/oauth/token` и `/provider/v1.0/`.

Пароль и Client Secret считаются секретами: копируйте их только в доверенные поля,
не размещайте в публичных логах и скриншотах.


## Версия 0.3.2: учётная запись для входа отдельно от Client ID

На вкладке «Авторизация» теперь два независимых блока:

- **Реквизиты приложения:** Client ID и Client Secret, указанные в Яндекс Диалогах.
- **Учётная запись для входа:** локальный логин и пароль, вводимые пользователем на странице `/oauth/authorize`.

Кнопка **«Создать новый пароль для входа»** сохраняет существующий логин (или ставит `home`, если логин пуст), но заменяет только локальный пароль. Client ID/Secret, ID пользователя, устройства и ранее выданные токены не затрагиваются. После генерации скопируйте пароль, сохраните изменения в настройках экземпляра, дождитесь перезапуска и повторите привязку. Первый генератор всего комплекта активен только когда все четыре поля OAuth изначально пустые. Для Яндекс Диалогов базовый `Endpoint URL` — `/provider/`; Яндекс добавляет `/v1.0` сам.


## Версия 0.3.4: исправление перехода OAuth на Яндекс

Chrome блокировал переход после успешного POST `/oauth/authorize`: CSP формы
содержала только `form-action 'self'`, а ответ сервера перенаправлял браузер на
`https://social.yandex.net/broker/redirect`. После первого POST одноразовый запрос
погашался, а повторное нажатие давало `Authorization request expired`. Теперь
`form-action` разрешает **только** собственный хост и проверенный адрес Яндекса
`https://social.yandex.net`, не снимая ограничения остальных источников.

Сначала обновите адаптер, затем **начните новую** привязку в «Дом с Алисой».
Показанные ранее формы авторизации повторно использовать нельзя. Client ID/Secret,
учётная запись OAuth, токены и существующие устройства не изменяются.


## 0.3.9 (2026-10-27)

- Based on 0.3.8, preserving independent read/write transforms and the Tuya curtain preset.
- Adds Yandex type `devices.types.openable` (Ворота), an `on_off` command mode for OPEN/CLOSE and a pause toggle for STOP (command-only by default).
- Search across device ID, name, type (internal and Russian label), room (including the ioBroker enum name), and description; multiple terms may appear in any order.
- Tuya preset operates exclusively on the chosen percent_control state. For this hardware 0% = fully OPEN, 100% = fully CLOSED. Read/write `range.open` are inverted, and `on_off` maps true to 0 / false to 100. Existing custom bindings are not changed automatically.
- In a command-mode binding `OPEN/CLOSE/STOP` has priority over the generic write transform; other bindings retain their transforms unchanged.
- Updating from 0.3.8 does not reset devices, OAuth settings or saved bindings. A restart and rediscovery in the Yandex app can be needed after adding a new device type.

Install via `npm install /tmp/iobroker.yandex-ud-bridge-0.3.9.tgz --omit=dev` from `/opt/iobroker`, then `iobroker upload yandex-ud-bridge` and restart the adapter instance.


## v0.3.11: единая настройка привязок

* Все функции используют одинаковое правило: **один основной объект ioBroker**. Для
  управляющих функций это адрес записи, для свойств — адрес чтения.
* Если устройство имеет отдельный read-only объект обратной связи, включите

* Существующие `stateId` (чтение), `commandId` (запись), `readTransform`,
  `writeTransform`, `commandMode`, `mapping` сохраняются. Сохранение настроек
  без изменений не мигрирует их в новый формат.
* Для командного объекта, который не содержит реальное состояние (напр.,
  ворота с `OPEN/CLOSE/STOP`), **не включайте «Яндекс может запрашивать значение»**,
  пока не выбран реальный объект обратной связи.
* У пресета Tuya `percent_control` по-прежнему 0 = открыто, 100 = закрыто.


## Подробная диагностика команд Яндекса (0.3.13)

В **Настройки адаптера → Дополнительно** включите «Включить подробный журнал команд (debug)», сохраните настройки и перезапустите экземпляр.
В стандартных логах ioBroker (уровень **info**) появятся сообщения `[YUD TRACE]` с общим `req=...`:

```text
[YUD TRACE] req=abc123 device=* HTTP POST /user/devices/action devices=1
[YUD TRACE] req=abc123 device=vorota_garage RECEIVE capability=on_off instance=on value=true binding=found
[YUD TRACE] req=abc123 device=vorota_garage BINDING read=(none) write=zigbee.0.f84477fffea7942d.state mode=enum_open_close
[YUD TRACE] req=abc123 device=vorota_garage TRANSFORM input=true output="OPEN" mode=enum_open_close
[YUD TRACE] req=abc123 device=vorota_garage WRITE setForeignStateAsync state=zigbee.0.f84477fffea7942d.state val="OPEN" ack=false
[YUD TRACE] req=abc123 device=vorota_garage RESULT setForeignStateAsync resolved; Yandex status=DONE; physical device operation NOT verified
[YUD TRACE] req=abc123 device=vorota_garage YANDEX capability=on_off/on result=DONE
```

Важно: `setForeignStateAsync resolved` подтверждает успешную отправку записи в States ioBroker, но **не** фактическое движение ворот и не подтверждение выполнения устройством Zigbee. В случае исключения будет `ERROR`, а Яндекс получит ошибку. Запросы OAuth, HTTP Authorization и секреты не логируются; подозрительные строки значений маскируются. Выключите режим после диагностики.


## v0.3.14 — преобразование значений без JSON

В редакторе любой функции выбери **Основной объект ioBroker**, затем в **Значения и команды** настрой преобразование для чтения и записи с помощью обычных полей. Данные по-прежнему хранятся в `readTransform`/`writeTransform` в прежнем формате; существующие устройства и настройки не мигрируются и не переписываются автоматически.

- **Таблица соответствий:** кнопка **Добавить значение** создаёт строку; текстовые значения `OPEN`, `CLOSE` сохраняются строками, числа `0`, `100`, `-2.5` — числовыми значениями. Для логических функций Яндекса показаны переключатели **Включено/Выключено**, которые сохраняют настоящие `true/false`. Для ioBroker state типа `boolean` также показываются логические значения, если тип известен из списка объектов.
- **Скопировать в обратную сторону:** переносит пары из одного направления в другое, меняя местами колонки. Если обратная схема неоднозначна, она не создаётся; порог можно указать отдельно для чтения.
- **Порог, инверсия, пересчёт диапазона:** отдельные подписанные числовые поля без JSON. Для старой конфигурации они показывают имеющиеся значения.
- Режим команд **Открыть/Закрыть** сохраняется для ранее настроенных устройств; числовые значения (`0`, `100`) в этих полях также распознаются как числа, слова — как строки.

### Пример для гаражных ворот

Выбери `zigbee.0.f84477fffea7942d.position` и в направлении **Запись: Яндекс → ioBroker** выбери «Таблица соответствий»: **Включено (true) → 100**, **Выключено (false) → 0**. В направлении **Чтение: ioBroker → Яндекс** выбери «Сравнение с порогом», условие **Больше (>)**, значение **0** (если любое открытое положение считается открытым). После сохранения обнови страницу Admin и проверь [YUD TRACE]: `output=100` либо `output=0` **без кавычек**.

Предупреждение: обратная таблица `0↔false, 100↔true` подходит только для точных конечных положений. Если устройство возвращает промежуточные значения 1…99, чтение через порог надёжнее.
